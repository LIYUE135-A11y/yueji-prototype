## 总开场（30 秒，可选）

我们在「美丽修行」里做了一套可运营的 AI 能力矩阵：C 端服务选购与售后体验，B 端兜住合规与人设配置。七个模块共用一套大模型接入与配置中心，但**职责严格拆分**——导购只荐真货、客服只答订单售后、测肤非医疗、商品审与内容审 prompt 分离。下面按模块讲我怎么从问题拆到落地。

---

## 1. AI 导购（`daogou`）

### 背景

美妆用户经常说不清货号，只会说「干皮、换季刺痛、预算 200」。站内其实有商品、评价、种草等资产，但纯聊天容易变成「话术好看、没有可点商品」，大模型还容易编造站外货或幻觉荐品；售后问题又容易串进导购。

### 目标

把自然语言需求转成 **1～3 个站内可售商品卡**，理由可解释；运营可配人设、快捷问与检索表白名单；模糊需求最多追问 1～2 个槽位；售后分流给客服；不满意可回写运营问题管理。

### 方案

核心原则：**检索 → 约束 → 生成**。先按表白名单（商品 / 评价 / 种草）召回候选并回填商品 ID，再把候选写进系统约束，LLM 只组织话术，**卡片 ID 必须来自候选集**。支持精准点名、功效模糊、跨表命中、多意图分区、多轮指代（「第二款更便宜」）。细节算法落在多表证据检索专项 PRD。

### 实施

- 配置：`AiConfigStore.getModule('daogou')`，运营可勾选关联表。  
- 工程：`collectGuideContext(Async)` + `llm-chat`；反馈 key `ai_guide_card_feedback_v1` ↔ 运营「AI导购问题管理」。  
- 双端：App 对话出卡；运营改 welcome/prompt/tables 热更新。  
- 验收侧重：有卡、卡可点、空结果不编造、表白名单生效、售后分流、fallback。

### 成果（面试可强调的价值）

打通「问需求 → 站内真货 → 可点购买」转化闭环；用检索约束压幻觉；把评价/种草从闲置 UGC 变成可消费的推荐证据；运营侧形成不满意会话可优化的闭环。

**一句话收尾：** AI 导购不是聊天机器人，是「受表白名单约束的智能选款助手」。

## 2. AI 内容审核（`nrsh`）

### 背景

社区种草、文章、动态、评论是活跃与转化来源，也是违规高发区：导流、辱骂、虚假功效、冒充官方。人工无法条条细看；它和商品货描审核侧重点不同，不能混用同一套 prompt。

### 目标

发布链路自动初审；首行「通过/驳回」+ 条目化理由；通过可分发并通知运营顶栏与用户 App 通知；驳回可改后重提；失败不默认公开高风险内容。

### 方案

送审标题/正文/话题等文本；强制两段式输出；状态机：草稿 → 审核中 → 通过 / 驳回 / 待人工。导购检索**只消费审核通过**的种草/评价。存疑可「通过 + 风险提示」供抽检。

### 实施

- App「发现→发布」、运营社区编辑保存发布均触发 `nrsh`。  
- 配置独立于商品审核；低温度偏保守。  
- 通知双写：运营消息中心 + App「消息→通知」。  
- 用例覆盖：导流驳回、正常通过、改稿重提、模型失败不放行。

### 成果

用自动化守门降低 UGC 风险敞口；用户感知「为什么被驳」可改；内容资产进入导购前先过合规闸，避免脏证据污染荐品。

**一句话收尾：** 内容审核是社区分发的守门员，不是改写器。

## 3. AI 商品审核（`shenhe`）

### 背景

上架前文案常踩广告法：绝对化（最/第一/100%）、医疗化（治疗/根治）。人工口径不一、只审标题不够；未通过商品若进导购会造成合规与体验双风险。

### 目标

对标题、卖点、详情做合规初审；严格「通过/驳回」首行；驳回引用原文片段；结果写回 `auditStatus` 可筛；终裁权仍在运营人工。

### 方案

组装商品字段送审；温度默认偏低；违规类型标签化（绝对化/医疗化/夸大承诺等）。解析失败或模型失败 → **保持待审核，绝不误标通过**。业务上未通过可拦截上架；导购默认不推未通过品。

### 实施

- 入口：商品管理单条/批量「AI审核」。  
- 配置键 `shenhe`；与 `nrsh` prompt 分离。  
- 列表展示驳回理由；支持改文案后重审。  
- 测评集盯召回率与误伤率。

### 成果

把货描合规前移到上架前；理由可定位便于改稿；与导购过滤联动，形成「审不过就不荐」的经营纪律。

**一句话收尾：** 商品审核是经营信息的合规初审机器人，终裁在人。

## 4. AI 客服（`kefu`）

### 背景

高频咨询是物流、售后、用券、操作路径。纯 LLM 容易编造运单号和退款金额；用户又常把选款问到客服，和导购边界糊；AI 解不了时需要无缝转人工且双端可见。

### 目标

7×24 有据答复本账号订单/售后；无依据说「暂未查到」禁止编造；选款引导导购；转人工进运营接待台；人设与表白名单可配。

### 方案

**先检索后生成**：查单/售后先走 `KefuStore`（订单/售后 store），事实块进上下文再调模型。意图分流：选款固定导流话术；转人工写「待接入」。状态文案与运营订单列表对齐。

### 实施

- C 端：欢迎语、快捷问、底部标签（转人工/发送订单/查看物流）。  
- 会话：`zhuangyan_kefu_sessions_v1`；人工态 `human_kefu_manage_v1`。  
- 运营回信 `source=ops` 同步 App。  
- 模型失败展示 `fallback` 并可转人工。

### 成果

重复咨询降本；幻觉风险用「有据才答」压住；职责清晰后导购/客服不再抢戏；转人工不断点。

**一句话收尾：** 客服是订单售后前台，不是导购，更不是审批赔付。

## 5. AI 撰写（`zhuanxie`，C 端「AI帮我写」）

### 背景

用户有图愿晒但写不出，或写成硬广触发合规；运营需要统一文风。若 AI 直接代发，风险与信任都不可控。

### 目标

发布流程里按用户框架扩写成种草/卖点草稿；遵守广告法红线；**不自动代发**；模型不可用时本地降级仍可演示；发布后仍走内容审核。

### 方案

用户填场景/产品/感受/适合谁 → system=`zhuanxie.prompt` 生成 → 回填编辑器由用户改 → 确认发布。禁绝对化、医疗化、虚构背书。与 `nrsh` 串联：帮写降门槛，审核守出口。

### 实施

- 入口：发现发布弹层「AI帮我写」。  
- 运营配名称、温度、prompt、maxTokens。  
- 空框架拦截；生成中防重复点击。  
- 可从订单「去种草」带商品名进框架（增强相关性）。

### 成果

提升发布完成率与内容供给；文风与红线可运营配置；「人确认 + 再审核」双保险，避免 AI 失控发文。

**一句话收尾：** 撰写是合规扩写助手，发布权永远在用户。

## 5b. AI 帮助（`bangzhu`）

### 背景

功能多入口散，新用户常迷路；静态 FAQ 难维护。帮助中心要「可对话解答怎么用 App」，且不能和客服查单、导购荐品抢戏。

### 目标

「我的 → 帮助」多轮对话（对齐 AI 导购）；运营可配 `bangzhu` 人设与 prompt；模型失败按关键词匹配知识库；快捷跳转导购/客服/测肤/订单。

### 方案

读运营配置 → 用户提问 →（可选）知识库匹配 → `LlmChat.chat` 自然语言回复；会话缓存；只写真实入口，不编履约事实。

### 实施

- 运营：AI配置 → AI帮助；知识库管理 → AI帮助。  
- App：`preview.html` 帮助对话面板 + `pages/ai-help`。  
- store：`zhuangyan_ai_config_v1.bangzhu`；知识库 `zhuangyan_ai_help_articles_v1`；会话 `yueji_ai_help_chat_v1`。

### 成果

降低「不会用」的客诉入口；把导航说明做成可运营的对话助手，而不是死 FAQ 或随机摇卡。

**一句话收尾：** AI 帮助是操作导航员，不是客服，更不是导购。

## 6. AI 测肤（`cefu`）

### 背景

肤质匹配影响美妆决策，用户需要低门槛自拍观察；但易被当成皮肤科诊断，照片质量差结论不稳，只有文案没有选品难转化，且易与识图（拍包装）混淆。

### 目标

正脸拍照/上传 → 结构化消费级报告（印象、特征、建议、注意）+ **选品关键词**驱动站内商品推荐；明确非医疗；图差要求重拍；可交接导购。

### 方案

免责声明 → 压缩上传 → 视觉大模型（`cefu.prompt`）→ 解析报告与【选品关键词】→ ProductStore 匹配在架且审过商品 → 失败用 fallback。与识图分流：正脸系统报告走测肤，包装认品走识图。

### 实施

- App：测肤 Tab / 引导页 / 报告页；读 `guideTitle`、welcome、quick。  
- 任务「完成首次 AI 测肤」可打点。  
- 合规抽检禁「诊断/根治」等措辞。  
- 报告页「按肤质问导购」带摘要与关键词上下文。

### 成果

把「拍一张脸」落到「可执行护理建议 + 可购推荐」；合规边界清晰；为导购提供肤质上下文，形成测肤→选品闭环。

**一句话收尾：** 测肤是消费级观察与选品助推，不是医疗诊断。

## 7. AI 识图（`shitu`）

### 背景

用户常拍瓶身、试色、截图问「这是什么、有没有同款」。纯文本导购覆盖不了看图；模糊图若硬答会编造货号；拍脸又可能本意测肤；识别后荐品不能脱库。

### 目标

上传商品/妆容图 → 品类与可见线索结论 + 建议 + 尽量匹配站内同款/相似款；看不清就说不确定；可交接导购或测肤；售后图导客服。

### 方案

传图 →（可选）同图/封面指纹预匹配 → 视觉模型 `shitu.prompt` → 关键词/预匹配 ID 在 `spgl` 检索出卡。匹配优先级：同图 > 品牌品名相似 > 品类关键词；无命中只出文字。

### 实施

- 主路径嵌在 AI 导购会话传图；配置模块独立。  
- 依赖运营「视觉大模型」全局配置。  
- 商品卡必须站内真实 ID；失败 fallback。  
- 分流文案：测肤诉求 / 破损售后分别导走。

### 成果

补齐「不会描述货号」的选购入口；同图命中提升「就是这款」的确定性；用不确定策略与站内匹配压幻觉、脱库荐品。

**一句话收尾：** 识图是看图给结论并尽量找站内同款，深度选款交给导购，系统测肤交给测肤。

## 横向对比（面试加分：体现全局观）

| 模块 | 服务对象 | 核心约束 | 绝不能做的事 |
|------|----------|----------|--------------|
| 导购 | 想买但说不清 | 站内真货推荐 | 编造商品/接售后 |
| 客服 | 已购有问题 | 有据查单售后 | 深度选款/乱编单号 |
| 识图 | 只会拍图 | 认品类+站内匹配 | 硬编货号/完整测肤 |
| 测肤 | 想知肤质 | 非医疗报告+关键词荐品 | 疾病诊断 |
| 撰写 | 写不出文案 | 合规草稿 | 自动代发 |
| 帮助 | 不会找入口 | 按主题操作指引 | 查单/深度荐品 |
| 商品审核 | 上架前货描 | 通过/驳回写回 | 误失败当通过 |
| 内容审核 | 社区 UGC | 分发守门+通知 | 与商品审混 prompt |

**共用底座：** 运营 AI 配置中心 + 通用/视觉大模型 + 双端 store 同步；**拆分原则：** 谁产生决策依据、谁对合规负责、卡片/状态以系统数据为准而非模型自由发挥。

## 追问预案（短答）

1. **为什么导购要先检索再生成？**  
   把「有没有这款货」从生成问题变成检索问题，模型只负责话术，从根上压幻觉。

2. **商品审核和内容审核为什么拆开？**  
   货描偏广告法绝对化/医疗化；UGC 偏导流、人身攻击、隐私。口径与测评集不同，混用会误伤或漏放。

3. **测肤和识图怎么防走错？**  
   入口文案 + 意图分流：正脸系统报告走测肤；包装/试色走识图；售后破损走客服。

4. **你怎么定义做成了？**  
   不讲虚指标：有卡率/幻觉抽检、有据答复率、违规召回与误伤、同图命中、帮写采纳且仍过内容审——都对应 PRD 验收与测试用例可回归。

## 口播时长与选用建议

| 面试时长 | 建议讲法 |
|----------|----------|
| 1～2 分钟 | 只讲总开场 + 横向对比表（职责拆分） |
| 3～5 分钟 | 开场 + **导购**完整五段 + 一句带过客服/审核边界 |
| 5～8 分钟 | 导购 + 客服（或导购 + 测肤→导购闭环）+ 横向对比 |
| 深挖某一模块 | 按该模块「背景→目标→方案→实施→成果」说满，末尾甩一句话收尾 |

**优先深挖顺序（含金量）：** 导购 → 客服 → 内容/商品审核（一对）→ 测肤/识图（一对）→ 撰写。

**叙事钩子（任选）：**

- 「我怎么防止大模型乱荐货？」→ 导购检索约束  
- 「客服和导购会不会抢活？」→ 意图分流  
- 「拍脸和拍瓶子怎么分开？」→ 测肤 / 识图  
- 「AI 写完会不会直接发出去？」→ 撰写不代发 + 内容审核

## 结尾金句（可选）

这套 AI 不是「接一个大模型聊天」，而是把美妆电商里**选购、服务、合规、内容供给**拆成可配置、可验收、可运营的能力，并且每一块都明确「以哪份真实数据为准」。
